# Conformance fixtures

Fixtures are protocol evidence and must not be regenerated with the engine under
test. LTX v2 fixtures are generated by the test-only `superfly/ltx v0.4.0`
oracle in `conformance/reference`, then decoded by Go and Rust and checked with
SQLite integrity checks. The generation script refuses to overwrite an
existing fixture; review and deliberately replace fixture bytes only when the
format contract changes.

The fixture matrix contains full snapshots of the same deterministic 128-row
SQLite database and timestamp `1700000000000`, generated by the test-only
reference encoder:

| File | SQLite page size | Expected logical contents |
|---|---:|---|
| `snapshot-512.ltx` | 512 | 128 rows; ID sum 8256; payload bytes 132480 |
| `snapshot-1024.ltx` | 1024 | 128 rows; ID sum 8256; payload bytes 132480 |
| `snapshot-4096.ltx` | 4096 | 128 rows; ID sum 8256; payload bytes 132480 |
| `snapshot-8192.ltx` | 8192 | 128 rows; ID sum 8256; payload bytes 132480 |
| `snapshot-65536.ltx` | 65536 | 128 rows; ID sum 8256; payload bytes 132480 |

`recovery-chain-4096/` adds a fixed incremental and compaction fixture set,
generated by the same pinned `superfly/ltx v0.4.0` oracle. The base contains
32 rows; delta 2 updates row 7 and inserts row 33; delta 3 updates row 7 again
and deletes row 2. The compacted snapshot covers TXIDs 1–2 and represents the
intermediate state. Go and Rust restore both the two-delta chain and compacted
snapshot and assert logical rows, row counts, and SQLite integrity.

| File | Meaning | SHA-256 |
|---|---|---|
| `recovery-chain-4096/snapshot-1.ltx` | Base snapshot, TXID 1 | `eb8f9048da1b64e280fd598fe2d983643e142726102701b206db517fa725b0cb` |
| `recovery-chain-4096/delta-2.ltx` | Update + insert, TXID 2 | `b62b62baf6934068c59221257cae5888a6cc9da72adf1de8b1b10d7cafa6b997` |
| `recovery-chain-4096/delta-3.ltx` | Update + delete, TXID 3 | `e0c10009c9d2c5ae55000dcc115642b956eb222de0c24dfcfb80aa8c144340b7` |
| `recovery-chain-4096/compacted-2.ltx` | Full snapshot for TXIDs 1–2 | `1bff7d5cc264039bb9e0c8660fcbcb8e31964eff32e8c11ff0598fd2074e31d0` |

Regenerate missing fixtures with `generate-ltx-v2-fixture.sh PATH PAGE_SIZE`; the
script refuses to overwrite existing bytes. The conformance runner restores all
five page sizes in both engines and verifies SQLite integrity and logical
contents. It also generates two-commit LTX capture chains independently with
Go and Rust, applies each chain with the pinned upstream `superfly/ltx v0.4.0`
CLI, then checks SQLite integrity and compares every restored row with the
source image. This is local format/restore evidence, not physical-durability
evidence. Generate the recovery chain fixtures with
`python3 conformance/generate-recovery-chain-fixtures.py`; it also refuses to
overwrite an existing fixture directory.
