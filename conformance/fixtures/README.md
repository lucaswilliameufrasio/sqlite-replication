# Conformance fixtures

Fixtures are protocol evidence and must not be regenerated with the engine under
test. LTX v2 fixtures are generated by the test-only `superfly/ltx v0.4.0`
oracle in `conformance/reference`, then decoded by Go and Rust and checked with
SQLite integrity checks. The generation script refuses to overwrite an
existing fixture; review and deliberately replace fixture bytes only when the
format contract changes.

The fixture matrix contains full snapshots of the same deterministic 128-row
SQLite database and timestamp `1700000000000`, generated by the test-only
reference encoder:

| File | SQLite page size | Expected logical contents |
|---|---:|---|
| `snapshot-512.ltx` | 512 | 128 rows; ID sum 8256; payload bytes 132480 |
| `snapshot-1024.ltx` | 1024 | 128 rows; ID sum 8256; payload bytes 132480 |
| `snapshot-4096.ltx` | 4096 | 128 rows; ID sum 8256; payload bytes 132480 |
| `snapshot-8192.ltx` | 8192 | 128 rows; ID sum 8256; payload bytes 132480 |

Regenerate missing fixtures with `generate-ltx-v2-fixture.sh PATH PAGE_SIZE`; the
script refuses to overwrite existing bytes. The conformance runner restores all
three page sizes in both engines and verifies SQLite integrity and logical
contents.
